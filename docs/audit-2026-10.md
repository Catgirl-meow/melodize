# Security, performance and edge-case audit (October 2026)

Scope: the companion (`companion/`) and the app's network, credential and
storage code (`lib/core/api`, `lib/core/models`, Android manifest). Checked
against Navidrome 0.64.0 (the production version) on a throwaway test server
(`scripts/test-navidrome.sh`).

## Fixed

| # | Severity | Area | Problem | Fix |
|---|----------|------|---------|-----|
| 1 | Critical | companion | `POST /api/songs/download` passed the URL straight to yt-dlp/deemix as an argument. `{"url": "--exec=..."}` ran a shell command as the companion user (needs the API key). `file://` and other schemes were also accepted. | URLs must be http(s) with no whitespace, and go after `--`. |
| 2 | High | app | Both companion clients accepted **any** TLS certificate for **any** host. Anyone on the network path could capture the API key, which can delete files and start downloads. | Self-signed certs accepted only for private hosts (LAN, loopback, Tailscale, `.local`/`.lan`/`.home.arpa`). |
| 3 | High | app | `resolveUrl` passed through absolute URLs from job responses, and `downloadTransition` sent the API key to them. | Absolute URLs must be on the companion's own origin. |
| 4 | High | companion | Single-threaded `HTTPServer` with no socket timeout: one client that opens a connection and stays silent blocks every request (no API key needed). | `ThreadingHTTPServer` + 30 s socket timeout. |
| 5 | Medium | Android | `allowBackup` defaulted to true, so adb and cloud backups held the server password, API key and Deezer ARL in plain text. | `android:allowBackup="false"`. |
| 6 | Medium | companion | Transition WAVs (authenticated) were sent with `Cache-Control: public`, so a caching reverse proxy could serve them without the key. | `private`. |
| 7 | Medium | companion | The ARL went into curl's argv (visible in `ps`) and wasn't validated (`;` could inject cookies). `.arl` file was written with the default umask. | ARL charset check, sent over stdin with `-K -`, file is 0600. |
| 8 | Medium | companion | Deezer detection was `"deezer.com" in url`, so `https://evil/?deezer.com` took the Deezer path. | Hostname check. |
| 9 | Medium | companion | Unbounded `Content-Length` (memory), non-object JSON and wrong field types caused crashes or dropped connections. A non-ASCII API key made `hmac.compare_digest` raise. | 1 MiB cap, type checks, JSON 500 on unexpected errors, byte comparison. |
| 10 | Bug | companion | `generate_transition` used an undefined `min_len`, so **every** rendered mix failed silently and fell back to a plain crossfade. | Fixed, with a regression test. |
| 11 | Bug | companion | `AnalysisCache.get` used `SELECT *` with positional indexes. The column order differs between fresh and migrated DBs, so `analyzed_at` held phrase JSON (fresh DBs) or `tail_silence` was misread (migrated DBs). | Named columns; also returns `phrase_positions`. |
| 12 | Perf | companion | Beat tracking (the slowest step) ran twice per song. | Reuses the first pass, so analysis takes about half as long. |
| 13 | Perf | companion | `get_all_stale` opened one SQLite connection per song on every batch request (tens of thousands for a large library). | One query. |
| 14 | Perf/Bug | companion | Large `song_ids` lists exceeded SQLite's parameter limit. Job registries grew forever. Downloads ran with no concurrency limit. | Chunked queries, 6 h job TTL, at most 3 concurrent downloads. |
| 15 | Bug | companion | `_load_tail` used `sf.info`, which fails on m4a and on older libsndfile builds without MP3/Opus support. | Falls back to `librosa.get_duration`. |
| 16 | Edge | app | Preferences were saved non-atomically. A crash mid-write left a truncated file, and `load()` then reset **all** settings, including the companion key. A single field with the wrong type had the same effect. | Temp file + rename (0600 on desktop), per-field tolerant parsing. |
| 17 | Edge | app | Song and job ids were put in companion paths unencoded. | `Uri.encodeComponent`. |

## Not changed (notes)

- **Subsonic auth in URLs.** Token and salt travel in the query string. That
  is inherent to the Subsonic API, and Navidrome doesn't reject reused salts,
  so the fixed cover-art salt adds no real exposure beyond what any stream
  URL already gives. Use HTTPS for remote access.
- **Plain-text password in the drift DB.** `ServerConfig.password` is stored
  unencrypted (Subsonic token auth needs the clear password). Moving it and
  the API key/ARL to the platform keystore (`flutter_secure_storage`) would
  be the next step, but it needs a migration.
- **`SubsonicClient.pingDetailed`** maps a wrong password (HTTP 200,
  `status: failed`) to `unreachable`. The setup screen is fixed separately
  by `checkConnection()` in the debug branch. Any remaining `pingDetailed`
  callers still show "unreachable" for bad credentials.
- **Phrase positions** are every 16 *beats* (4 bars), although the comment
  says 16 bars. Left as is, because the app's transition planner is tuned
  to it.
- The companion still binds `0.0.0.0` by default. Set `"bind": "127.0.0.1"`
  behind a same-host reverse proxy.

## Tests

- `flutter test`: 182 tests pass. The live suite in `test/live/` (8 tests) runs
  when `MELODIZE_TEST_*` is set (`eval "$(scripts/test-navidrome.sh env)"`)
  and is skipped otherwise.

  see CLAUDE.md for the `uv` command).
